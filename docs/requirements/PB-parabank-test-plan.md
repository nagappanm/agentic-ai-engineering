## Blocked — clarifications owed before these can run

- **TC-002** (high) Invalid credentials keep the customer off Accounts Overview and show an error
  - UNKNOWN: the exact error text and its placement on the page are not specified by PB-2 — clarify the expected message and where it renders before asserting on it
- **TC-004** (high) The password is never echoed back in plain text during authentication
  - UNKNOWN: the banking constitution forbids echoing plain-text passwords, but PB-1 and PB-2 state no logging requirement — confirm this is in scope and whether server logs are also to be checked
- **TC-009** (high) A transfer of exactly zero is rejected
  - UNKNOWN: the banking constitution requires zero to be treated as a boundary case, but PB-4 does not state the expected handling — clarify whether a zero transfer is rejected, and with what message
- **TC-010** (high) A transfer of a negative amount is rejected
  - UNKNOWN: PB-4 does not state how a negative amount is handled — clarify whether it is blocked client-side, rejected server-side, or normalised
- **TC-011** (high) A transfer of more than the available balance is rejected
  - UNKNOWN: the requirement explicitly leaves insufficient-funds behaviour open — clarify whether the transfer is refused, allowed to overdraw, or queued, before this case can assert anything
- **TC-013** (high) A completed money movement is recorded in an auditable trail
  - UNKNOWN: the banking constitution requires an audit trail covering who, what, when and amount, but PB-5 and PB-6 do not state that the actor is recorded or visible — clarify what the audit record must contain and where it is inspected
- **TC-020** (high) The session no longer grants access to account pages after logout
  - UNKNOWN: the banking constitution requires session expiry on logout and after inactivity to be asserted explicitly, but no logout or timeout behaviour is stated in PB-1 to PB-10 — clarify the logout flow and the inactivity timeout, or confirm they are out of scope for this requirement
- **TC-003** (medium) Submitting the login form with both fields empty is rejected
  - UNKNOWN: whether an empty submission is blocked client-side or reaches the server is not specified — clarify the expected behaviour and message
- **TC-012** (medium) A transfer amount with more than two decimal places is handled consistently
  - UNKNOWN: currency rounding is required as a boundary case by the banking constitution but no rounding rule is stated — clarify the rounding mode and the number of decimal places accepted
- **TC-015** (medium) Transactions can be found by amount
- **TC-017** (medium) Transactions can be found by date
  - UNKNOWN: the accepted date format is not stated and the one observed value is ambiguous between DD-MM-YYYY and MM-DD-YYYY — clarify the format before any date can be entered deterministically
- **TC-016** (low) Searching by an amount with no matching transactions returns an empty result
  - UNKNOWN: PB-8 does not state what an empty result renders — clarify whether a message is shown or the table is simply empty
- **TC-018** (low) A date outside the account's transaction history returns an empty result
  - UNKNOWN: the date format is not established, so this case cannot be executed until TC-017's clarification is resolved
